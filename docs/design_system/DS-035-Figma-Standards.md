# Figma Standards

> "A clean design file is as important as clean code."

## Purpose

Defines the standards for organizing, maintaining, and scaling every Figma file used to design Ascend.

---

## Philosophy

Figma files should be easy to navigate, version, review, and hand off.

Every designer should be able to understand a file without prior context.

---

## File Structure

Recommended pages:

- Cover
- Foundations
- Components
- Patterns
- Screens
- Prototypes
- Archive

---

## Component Library

Maintain a single source of truth for:

- Foundations
- Components
- Icons
- Templates
- AI Components

Publish updates through a managed library.

---

## Variables

Use Figma Variables for:

- Colors
- Typography
- Spacing
- Radius
- Motion
- Elevation

Variables should mirror design tokens.

---

## Auto Layout

All production-ready components must use:

- Auto Layout
- Constraints
- Responsive resizing
- Component properties
- Variants

---

## Naming

Follow DS-034 naming conventions for:

- Pages
- Frames
- Layers
- Components
- Variants
- Variables

---

## Documentation

Each component page should include:

- Purpose
- Anatomy
- Variants
- States
- Usage guidelines
- Accessibility notes

---

## Handoff

Designs must include:

- Developer annotations
- Token references
- Interaction notes
- Responsive behavior
- Accessibility guidance

---

## Engineering Alignment

Figma components should map one-to-one with engineering components whenever possible.

---

## AI Context

AI-generated designs should comply with these standards before entering the design review process.
