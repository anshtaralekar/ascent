# API AI/Agent Interface Standards

## Purpose

Defines how AI agents, models, and tool-calling systems interact with Ascend APIs safely and predictably.

## Philosophy

An AI agent is an untrusted decision-making component operating inside a trusted application architecture. Its permissions must be explicit and bounded.

## Agent Boundary

The standard flow is:

**User/Workflow → Agent Orchestrator → Authorized Tool Interface → Application Service → Data/External System**

The model should not receive unrestricted infrastructure access.

## Tool Design

Every tool should define:

- Name
- Purpose
- Input schema
- Output schema
- Required permissions
- Side effects
- Idempotency
- Timeout
- Failure semantics

## Least Privilege

Tools should expose the smallest capability required.

Prefer:

**create_task**

over:

**execute_arbitrary_sql**

and similarly narrow capabilities should be used for files, communications, configuration, and administrative operations.

## Input Validation

Tool arguments generated by models must undergo normal server-side validation.

Model-generated input is not trusted input.

## Authorization

Authorization must be evaluated independently of model instructions.

The model cannot grant itself permissions by generating claims, tenant IDs, roles, or approval statements.

## Tenant Isolation

Every AI operation must retain trusted tenant context.

Semantic retrieval must apply authorization before returning source material.

## Side Effects

Side-effecting tools must define:

- Confirmation requirements where appropriate
- Idempotency
- Audit events
- Retry behavior
- Rollback or compensation where possible

## Human Approval

High-impact actions may require explicit human approval before execution.

Approval must be represented as a trusted application state, not merely text in the model context.

## Structured Outputs

AI responses used programmatically should use validated schemas.

Reject malformed structured output rather than silently executing it.

## Streaming

Streaming interfaces must define:

- Event framing
- Completion state
- Error behavior
- Cancellation
- Partial-output semantics

## Tool Errors

Tool errors should be machine-readable and should not expose secrets, stack traces, or internal infrastructure details to the model.

## AI Provider Independence

Where practical, the application should separate provider-specific model APIs from domain tool interfaces.

## Usage Controls

Apply:

- Rate limits
- Token/usage quotas
- Concurrency limits
- Timeouts
- Cost controls

## Auditability

Record important agent actions with:

- Workflow/run ID
- Tool identity
- Resource affected
- Result category
- Actor/workflow identity

Do not log sensitive prompts or secrets unnecessarily.

## Prompt Injection

Retrieved or user-provided content must not automatically become trusted instructions.

Tool authorization remains authoritative even when content attempts to override system behavior.

## Anti-Patterns

Avoid:

- Direct unrestricted database access
- Model-controlled authorization
- Arbitrary code execution tools
- Unvalidated tool arguments
- Hidden side effects
- Treating retrieved text as trusted policy

## AI Context

AI coding agents must follow these rules whenever implementing agent endpoints, tool APIs, structured model outputs, retrieval interfaces, or AI workflow services.
